## Week 2 — How Text Becomes Numbers { #w02 }

Twenty-seven slides: tokens, one-hot, the counting era and its ceiling, the
learned-embedding idea, the geometry, word2vec, and the arrival of context.
Four of them are discussion prompts — in class we stop and argue before the
next slide answers the question.

[:material-download: Deck for presenting (PPTX, ~11&nbsp;MB)](media/W02_How_Text_Becomes_Numbers.pptx){ .md-button }
[:material-printer: Print edition (PPTX, ~3&nbsp;MB)](media/W02_How_Text_Becomes_Numbers_print.pptx){ .md-button }

Two files on purpose. In the **presenting deck** the GIFs animate in slideshow
mode (F5) — but anywhere a slide is rendered *still* (the editor, Notes Page
view, printing, PDF export) you get each animation's first, nearly-empty
frame. The **print edition** is the same 27 slides and the same speaker notes
with every animation replaced by its final, fully-built frame — use it for
printing notes pages, handouts, or reading the deck as a document.

### How this deck was made { #how-this-deck-was-made }

This deck is itself a course artifact: it was built by prompting, and the
process is exactly the loop this course wants you to practise on your own
project. **Attribution, stated plainly:** every slide was generated by Claude
Code writing Python, from instructor prompts, with every frame reviewed before
it reached this page. That sentence is what an honest AI citation looks like —
see the [AI policy](../syllabus.md#using-ai).

Nothing here was drawn by hand. Each slide is a small Python script that
renders matplotlib frames and assembles them into a GIF; a build script
collects the GIFs into the PPTX; the site publishes the same files below. The
scripts live in
[`scripts/` on GitHub](https://github.com/Nalaquq/llms-and-you/tree/main/scripts),
and the GIFs and deck are **never committed** — they are regenerated from the
scripts on every deploy, the same rule the session pages follow.

The deck took four prompts. Watch what each one is doing:

**Prompt 1 — the brief.** *"I want to create a powerpoint that covers all the
concepts for week 2 day 1 (embeddings)… feature gifs of concepts… the feeling
of 3blue1brown's gif animations… matched the style of this website (I like
the dark theme)."* Plus two references: slide-generation scripts from a
previous course to reuse the pattern, and a Cornell deep-learning deck to
absorb content from. Note what makes this prompt work: it names the audience,
the aesthetic, a house style to imitate, and source material — constraints,
not vibes. The result was a complete 21-slide draft.

**Prompt 2 — deepen a weak spot.** *"Maybe we should show an example that
helps the students understand how the columns are created… a rotating 3
dimensional graph… and then discuss that it can be in very high dimensions
and the pros and cons of this."* The first draft asserted that embeddings are
scorecards; this prompt made the deck *earn* the claim. Two slides appeared:
one deriving a scorecard column from co-occurrence counts, one tilting the
familiar 2-D scatter into 3-D to reveal an axis that was always there.

**Prompt 3 — add the pedagogy.** *"I want to introduce some slides that
include a question… 1–3 questions that should serve as discussion prompts at
critical junctures… The goal is to see that these approaches developed to
compensate for problems."* Four discussion interstitials appeared, each placed
just before the slide that exposes the current method's flaw — so the room
predicts each failure before seeing it.

**Prompt 4 — argue with the tool.** *"One confusing thing about this is that
we cover learning associations with embeddings before BOW and TF-IDF. But
these simpler techniques do not learn embeddings correct? So wouldn't we want
to cover these first?"* This is the important one. The model had ordered the
deck motivation-first; the instructor pushed back with a reason, the model
agreed the criticism was structural, and the deck was reordered chronologically
— counting fails *before* the learned-embedding idea appears. **Prompting is
not accepting.** The best change in this deck came from disagreeing with it.

Four prompts, four decisions, each recorded with its reasoning — which is to
say: this section is an ADR log wearing a different hat, and it is the shape
your own [project log](../guides/writing-adrs.md) should have. The structural
decision behind this page is recorded properly in
[ADR-019](../adr/index.md#adr-019-host-the-lecture-decks-and-publish-how-they-were-made).

To rebuild everything from the scripts:

=== "macOS / Linux"

    ```bash
    pip install -e ".[slides]"
    cd scripts
    for f in gen_*.py; do python "$f"; done
    python build_deck.py
    ```

=== "Windows (PowerShell)"

    ```powershell
    pip install -e ".[slides]"
    cd scripts
    Get-ChildItem gen_*.py | ForEach-Object { python $_.Name }
    python build_deck.py
    ```
